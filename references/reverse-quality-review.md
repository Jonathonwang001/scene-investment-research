# 严格反向审查台账｜场景驱动战略投资研究技能

> 审查目的：不因已有完整流程而降低标准。逐项验证技能能否在不依赖既有企业信息的前提下，生成具有机构级研究深度、MBB式领导叙事、可执行投资动作和可编辑交付的材料。

## 审查结论概览

| 审查维度 | 初始状态 | 主要缺口 | 必须补强动作 |
|---|---|---|---|
| 企业视角与问题定义 | 基本完整 | 缺少从公司战略到投资组合的明确问题树和“什么不值得做”的反事实 | 增加战略问题树、反事实和机会成本判断 |
| 场景—生态—产业链 | 完整 | 未明确如何避免场景、生态或技术卡片并列堆砌 | 增加“每页角色—承接—下页”的叙事与收敛检查 |
| 技术与成本 | 基本完整 | 总拥有成本较充分，但缺少基准方案、成本拆解、敏感变量和倒挂情景 | 增加基准方案、单位经济、敏感性和不成立条件 |
| 商业模式与市场 | 有框架 | 缺少价值池、付费意愿、竞争传导、现金流归属和市场规模反推规则 | 增加价值池—收费单元—现金流归属—市场边界四层模型 |
| 战略投资动作 | 基本完整 | 缺少“自建/采购/合作/少数股权/控股”的反事实比较与资本配置逻辑 | 增加Make–Buy–Partner–Invest–Acquire决策树和交易工具边界 |
| 证据与客观性 | 较完整 | 未强制列出反方、基准概率、关键未知数和结论可推翻条件 | 增加主张台账、负面证据、基准率与结论降级规则 |
| MBB式PPT | 不足 | 有单向故事线要求，但缺少行动标题、金字塔、MECE问题树、页面类型、关键洞察框、审稿表 | 增加MBB演示设计资源和PPT反向审稿门槛 |
| 双报告与主表 | 基本完整 | 缺少跨文件“单一事实源”、版本变更和数值一致性机制 | 增加事实源、版本、交叉引用和变更审计机制 |
| 可编辑交付 | 基本完整 | 缺少对图表、图形、源数据、演讲稿和最终链接的具体可编辑性检查 | 增加可编辑对象清单和交付次序 |
| 去敏与可复用 | 基本完整 | 缺少语义去敏检查和“实例数据不得转入模板”的硬门槛 | 增加实体、数值组合、专有叙事、路径和附件的语义去敏规则 |

## 反向审查问题清单

### A. 研究本质是否正确

- [ ] 是否先回答“[目标企业]为何需要战略投资，而不是自然增长、采购、合作或内部研发”？
- [ ] 是否将企业战略、客户问题、产业价值池、产品节点和资本动作拆成相互独立、共同穷尽的层次？
- [ ] 是否至少形成“维持现状”“采购/合作”“内部产品化”“少数股权”“控股/并购”五种反事实？
- [ ] 是否说明每个方向的机会成本、资源占用和最坏情况，而非只写正向协同？

### B. 证据与客观性是否充分

- [ ] 每项改变优先级的主张是否有来源、证据等级、反方证据、未知数、结论可推翻条件？
- [ ] 是否把法律义务按产品、地域、时间、主体/角色拆开，而非将同行经验写成法律结论？
- [ ] 是否把企业材料、管理层判断、第三方线索、公开事实和模型假设显式区分？
- [ ] 是否以零协同、零数据权利、零订单导入作为基准情景，而非默认获得协同？

### C. 技术、成本与商业模式是否闭环

- [ ] 是否比较技术性能、可靠性、良率、认证、供应链、部署、运维、切换、质保和退出，而不只比较单价或实验指标？
- [ ] 是否按“价值池→付费方→收费单元→现金流归属→可获得收入”判断市场空间？
- [ ] 是否区分一次性硬件、项目实施、订阅、资产服务、交易/节省分成，并说明各自的毛利、复购、资本占用和风险？
- [ ] 是否明确核心敏感变量及其反向变化时结论是否成立？

### D. 战投卡位是否真实

- [ ] 是否点名具体产品/算法/材料/设备/软件/公司类型，而不是赛道或抽象能力？
- [ ] 是否说清企业可控制的项目接口、可用的规格/测试/采购/合同动作，以及企业不可控制的事项？
- [ ] 是否写清自建、采购、合作、联合开发、投资和并购的适用边界，并避免“战投=合作”或“投资=控制系统”混用？
- [ ] 早期标的可未盈利时，是否用团队、原型、工程路线、TCO、项目验证和独立外部市场替代成熟公司财务门槛？

### E. MBB式汇报是否真正成立

- [ ] 每页标题是否为行动标题，即一个可判断的完整结论句，而非“市场分析”“生态地图”“机会方向”等描述词？
- [ ] 页面是否按金字塔逻辑安排：结论先行、3—5个互不重叠的支撑论点、下一页继续证明？
- [ ] 每个数字、图表、矩阵或地图是否有一条“这意味着什么”的关键洞察，而非仅展示素材？
- [ ] 是否选择了与问题匹配的页面类型（问题树、逻辑箭头、矩阵、瀑布、甘特、As-Is/To-Be、结论页），而不是用表格填满PPT？
- [ ] 是否保留用户模板的品牌风格、页眉页脚和页数约束；在此基础上做到克制、留白、清晰、可编辑与视觉统一？

### F. 跨文件与去敏是否可靠

- [ ] 是否将“企业事实卡、机会ID、产品名称、阶段、法规日期、来源编号”作为单一事实源，并同步到报告、Excel、PPT和导航？
- [ ] 是否先完成最后一次PPT呈现，再更新导航和Excel中的最终链接？
- [ ] 是否对所有模板、示例、脚本、附件、注释和文件路径进行名称、证券代码、客户、地点、金额、独有表述与数值组合的语义去敏？
- [ ] 是否以可编辑对象为单位验收：PPT文字/形状/箭头/表格/图表，Excel源数据/公式，Markdown正文/表格，Mermaid源文件/CSV/Python源文件，演讲稿和导航？

## 审查后的补强原则

1. **先反事实，后建议。** 不先证明“为什么不能仅采购/合作/自建”，不进入战投建议。
2. **先价值池，后市场规模。** 不先说明谁付费、如何收费、成本如何传导、现金流归谁，不引用总市场数字支撑估值。
3. **先全链，后节点。** 不先展示上中下游、数据/服务/责任与替代路线，不列卡位产品。
4. **先项目接口，后股权。** 不先说明企业可怎样通过规格、测试、采购、服务或合同合法导入，不讨论投资后协同。
5. **先结论标题，后图表。** 每页先写一条行动标题和其必须证明的事实，再选择最少、最适合的MBB页面类型。
6. **先单一事实源，后多文件。** 不在报告、Excel、PPT中分别改写同一结论，避免版本分叉。

## 本轮逐项审查发现与修订决定

| 编号 | 严格审查发现 | 可能造成的后果 | 修订决定 |
|---:|---|---|---|
| 01 | 主说明仅要求“单向故事线”，没有强制行动标题、结论页、执行摘要和页面问题定义 | PPT可能仍是正确素材的并列罗列，领导无法在数分钟内抓住决策 | 新增MBB故事线与页面角色规范；PPT必须先写行动标题和单页关键问题 |
| 02 | 未强制先做“维持现状/采购/合作/自建/投资/并购”的反事实比较 | 容易把任何战略问题直接导向股权投资 | 新增资本工具决策树、机会成本、零协同基准和资本退出逻辑 |
| 03 | 虽有TCO字段，但缺少基准方案、成本传导、敏感变量、价格下降和成本倒挂测试 | 可能把技术参数优势误判为企业经济性优势 | 增加TCO基准、单位经济、价格/量/良率/利用率敏感性及价值池归属要求 |
| 04 | 市场规模规则有TAM/SAM/SOM，但没有从价值池、付费方和收费单元反推的强制顺序 | 容易出现“大市场、小收入”或材料单价逻辑被误估值 | 固化“价值池→付费方→收费单元→现金流归属→可获得收入”顺序 |
| 05 | 技术路线强调对标和反证，但未要求“客户采用、认证、供应链、服务责任”同时成立 | 易把研发路线、专利或样机误写成可交付能力 | 新增技术商业化五关：工程、认证、供应、采购、责任/服务 |
| 06 | 场景—生态—产业链逻辑较强，但没有将战略问题树和企业能力邻接性显式化 | 场景可能很全面，但与企业战略或资源投放不能形成MECE决策 | 增加战略问题树、能力邻接图、价值链价值池及组合优先级框架 |
| 07 | 没有项目组合层面的“相关性/独立性/资源冲突/时序”判断 | 可能堆积多个单点机会，却无法形成资本配置次序 | 新增投资组合矩阵和资源占用/共享能力检查 |
| 08 | 数据与事实分级完备，但缺少“单一事实源、变更日志、跨文件字段字典” | 报告、Excel、PPT和演讲稿容易版本分叉 | 新增主事实表、字段字典、版本冻结与最后呈现后更新导航流程 |
| 09 | 可编辑交付有总体要求，但对PPT图表源数据、演讲稿、视觉检查和导出前后版本未形成逐项验收 | 可编辑性可能停留在口头承诺，重点页仍可能难读 | 增加可编辑对象验收与MBB视觉审稿清单，要求重点页渲染核验 |
| 10 | 去敏规则偏词汇级，缺少语义去敏和反向识别测试 | 即使删除企业名，数值组合、独有叙事和文件路径仍可暴露上一项目 | 增加实体/数值组合/专有叙事/路径/附件五类去敏审计和独立阅读测试 |
| 11 | 现有自动脚本只能发现文本与结构提示，不应被误用为“已完成研究”的证明 | 可能形成自动检查通过但投资判断不充分的假象 | 脚本明确定位为初筛；新增人工红队审查与“证据不足不出强结论”停止规则 |

> **总体判断：** 初始技能已具备从场景到具体战投产品的核心骨架，但若不补上MBB故事化、战略反事实、价值池/单位经济、组合资本配置、单一事实源与红队反证六个层面，仍可能产出“研究很全但领导难以决策”的材料。修订后必须优先让每页和每个表格服务于一个可授权、可停止、可追问的结论。

## 一级市场与技术产业化专项反向审查

| 风险性误判 | 红队必须追问 | 合格结论标准 | 直接否决或降级条件 |
|---|---|---|---|
| 用成熟公司指标否决早期标的 | 当前阶段需要的是订单/认证/盈利，还是原理、样机、工艺、成本或团队证据？ | 按原理、工程样机、中试、扩产分别设置证据与升级闸门 | 将未盈利、未量产或未全套认证作为唯一否决理由 |
| 将技术代际等同于商业化 | 它在什么具体场景优于主流路线；良率、封装/系统、可靠性和TCO何时越过拐点？ | 把目标应用、主流/替代路线、工艺、良率、成本曲线、客户导入和责任路径写清 | 只以“更先进”“第N代”或实验室峰值参数主张替代 |
| 用总市场支持材料/部件估值 | 价值最终由谁支付；按克/件/模组/订阅/交易还是结果分成收费；企业实际拿到哪一层现金流？ | 自价值池反推付费方、收费单元、现金流归属、可服务市场和可获得收入 | 用下游系统总市场或未来平台想象直接给当前材料/硬件估值 |
| 假设商业模式升级必然发生 | 企业是否真有定价权、结算权、渠道、数据/合同权利与服务承接能力？ | 基准情景按已验证商业模式；升级模式只作为单列上行情景 | 同时把收入、毛利、估值倍数和退出概率全面上调 |
| 将国产替代自动计入溢价 | 真实依赖/受限、可用、可制造、TCO、切换、自主性、合规是否分别成立？ | 七项条件逐项留有证据与不成立处理；溢价只出现一次且可追溯 | 仅因国产、受关注或地缘紧张就提高基础估值 |
| 将项目验证变成成熟采购验证 | 是验证技术/工程/成本假设，还是要求标的已拥有大规模订单？ | 早期以可证伪实验、原型、工艺重复性、成本树和联合验证为主；后期再看采购/回款质量 | 把“没有大客户订单”写成所有阶段的停止条件 |

> **审查结论规则：** 对早期技术标的，严谨不是要求其伪装成成熟公司，而是要求每一个尚未实现的假设都有可证伪的技术、工程、成本和商业化路径。无法量化的风险必须写出数据缺口和对结论的影响，而不是用乐观市场规模、代际名词或供应安全叙事填补。
