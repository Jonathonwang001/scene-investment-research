# 研究框架｜从企业能力到战略投资卡位

> 仅在启动新研究、重构既有材料或发现“场景很多但投资结论不清”时读取。本文件定义工作底稿和每条产业链的最低展开颗粒度。

## A. 企业事实卡

| 字段 | 必填内容 | 证据与边界 |
|---|---|---|
| 企业定位 | 客户付费对象、主营业务、价值创造位置 | 不用行业标签代替事实 |
| 已有能力 | 自研、整合、采购、交付、运维、渠道、服务 | 分清已量产、在研、试点和设想 |
| 经营现实 | 增长/盈利约束、地域、客户结构、竞争、回款、资本约束 | 管理层目标不是预测依据 |
| 项目接口 | 企业能控制的规格、设计、采购、测试、交付、服务、合同接口 | 不假设可控制客户或供应商数据 |
| 战略边界 | 不自研、不进入、不投资、仅合作的领域及原因 | 明确人力、资本、认证、时间和责任约束 |

### 场景优先级的判断

优先看客户问题是否同时满足以下任一组合：高损失且持续、单点小但可规模复制、强监管/认证约束、存量资产责任、与企业现有系统有共同部件/数据/交付接口。不要用“市场大”作为唯一优先级。

## E. 完整产业链深钻模板

每条重点产业链必须完整回答下表的八个模块。宁可少选方向，也不要压缩为技术词堆砌。

| 模块 | 具体写法 | 必要反证 |
|---|---|---|
| 1. 场景问题 | 谁在何种场景遭遇什么问题，当前方案为什么解决不足，造成何种成本/风险/损失 | 当前成熟方案是否已足够好；是否只是小众需求 |
| 2. 完整产业链 | 上游材料/基础、部件/软件、中游装备/系统、下游客户/交付/服务/循环；标出责任和价值交接 | 是否遗漏认证、数据、服务、回收或渠道等决定采用的环节 |
| 3. 技术路线 | 主流、前沿、互补、替代路线；分别说明适用场景 | 是否把“新”误当“好”；成熟替代为何不能解决 |
| 4. 工程与TCO | 良率、成本、可靠性、认证、供应链、安装、运维、质保、切换和退出成本 | 是否仅比较采购价；是否忽略改造、维护和责任成本 |
| 5. 具体卡位产品 | 明确产品、算法、材料、设备或公司类型；写清交付形态 | 是否只是泛领域、项目定制或普通标准件 |
| 6. 企业接口 | 企业自做/整合、采购、合作、联合开发、内部产品化和战投的分工 | 企业是否真的拥有规格、项目或服务接口 |
| 7. 商业模式 | 付费方、收费单元、ASP/订阅/按量/分成、复购、市场边界 | 是否把总市场当公司收入；是否将一次性收入当平台收入 |
| 8. 阶段与闸门 | 近期、中期、远期动作；升级和停止证据 | 是否把投资后自然获取的数据、订单、接口或控制权写成前提 |

## F. 卡位产品卡

对每一个保留的战投卡位，逐项填写以下模板。字段不得为空；无法确认时填写“待核验”并说明其对结论的影响。

| 字段 | 填写要求 |
|---|---|
| 名称 | 中文业务名称优先；括号中写具体产品、算法或公司类型 |
| 场景问题 | 用客户、交付、责任或成本语言描述 |
| 产业链位置 | 上游/中游/下游及与系统、服务、循环节点的关系 |
| 主流/替代路线 | 至少说明一个主流和一个替代或反方路线 |
| 工程成熟度 | 样机、量产、认证、良率、安装、运维和可靠性状态 |
| 总拥有成本 | 采购、部署、维护、责任、合规、切换和退出成本 |
| 企业为何能切入 | 现有产品、系统、项目、采购或服务的真实接口 |
| 企业获得什么 | 成本改善、准入能力、系统差异化、服务收入或选择权；不要承诺无法控制的权利 |
| 商业模式 | 付费方、收费单元、复购与外部市场边界 |
| 战投工具 | 采购、合作、联合开发、内部产品化、小额期权、少数股权、增持或不做 |
| 近期动作 | 可执行的规格、测试、合同、样本或项目动作 |
| 升级/停止条件 | 满足什么才进入股权；失败时为何停止 |

## H. 法规与标准机会的专用判断

法规不是自动形成投资机会。对任何法规/标准驱动方向，按以下顺序判断：

1. 核对法规原文、适用地域、产品分类、责任主体、生效/过渡日期和二级实施规则。
2. 将法律义务还原为“**哪一段责任链必须提供什么证据、产品或服务**”。
3. 比较各行业已成熟技术：物理身份载体、数据模型、事件追踪、规则校验、可信证据、连接器、运行诊断、回收/处置工具等。
4. 明确哪些只是通用设施、哪些能嵌入企业现有系统、哪些可被做成独立产品；不能因法规重要就投通用标签、咨询或产能。
5. 以项目规格、供应商准入、测试、合同责任和客户授权建立“事实交付标准”；不得宣称企业天然制定行业标准。

## I. 可复用的领导问答

| 领导常问问题 | 必须直接回答 |
|---|---|
| 为什么是这个场景？ | 客户结果、损失、现有方案缺口和企业接口 |
| 这和企业现有业务有什么关系？ | 共同部件、系统、项目、服务或客户接口；没有则承认 |
| 具体投什么？ | 产品/算法/材料/设备/公司类型，不能只说赛道 |
| 为什么不自研或直接采购？ | 壁垒、研发/认证/时间成本、系统责任和可产品化空间 |
| 为什么现在做？ | 法规、客户、工程、成本或竞争窗口；不是热点 |
| 市场有多大、怎么赚钱？ | TAM/SAM/SOM边界、收费单元、付费方、复购和价值分成 |
| 有大公司在做，为什么还能切入？ | 不复制其重资产或封闭体系；从企业可控制的系统责任节点切入 |
| 投资后能得到什么？ | 只能写可合同化、可测试、可采购或可治理的事项 |
| 什么情况下不投？ | 标准件化、无法降TCO、无企业接口、无独立外部市场或不可落实责任 |
