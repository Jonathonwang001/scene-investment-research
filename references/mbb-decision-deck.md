# MBB式战略投资决策演示规范

> 创建、重构或审查任何领导PPT时读取。使用此文件与 `consulting-ppt` 技能共同工作：**借用MBB的故事化、行动标题、MECE、度量与审稿纪律；保留用户指定的企业模板、品牌色、字体、页眉页脚和可编辑性要求。** 不把MBB理解为强制使用某一种颜色或样式。

## 1. 演示的唯一目标

演示不是把报告缩短，也不是给Excel加图。它必须使决策者在有限时间内回答四个问题：

1. **为什么必须关注这一问题？** 客户、经营、技术、法规或竞争的真实变化是什么；不行动的代价是什么。
2. **真正该解决什么？** 通过MECE问题树将广泛场景/生态收敛为少量系统责任与价值池问题。
3. **具体应布局什么？** 由完整产业链、路线比较、总拥有成本和企业接口收敛为具体产品/算法/材料/设备/软件或公司类型。
4. **现在授权什么、何时停止？** 明确项目动作、资本工具、资源需求、升级条件和停止条件。

## 2. 先写故事线，再制作页面

在创建PPT前，必须完成 `templates/slide-content-outline.md`。先写每页的“行动标题—必须证明的事实—最合适的页面类型—关键洞察—下一页承接”，再设计页面。

### 金字塔叙事

| 层级 | 应回答的问题 | 页面应呈现的结论 |
|---|---|---|
| 顶层结论 | 本次需要的决策/授权是什么 | 三条以内的可行动结论、资源/风险边界 |
| 第一支撑 | 为什么现在、为什么是该企业、为什么不是简单采购/合作 | 企业事实、场景压力、生态责任、反事实比较 |
| 第二支撑 | 具体投什么、为什么有价值、为什么做得到 | 完整产业链、路线比较、TCO、商业模式、项目接口 |
| 执行动作 | 先做什么、如何验证、如何进入/退出 | 路线图、决策闸门、负责人、里程碑、停止条件 |

不要以“全场景地图”“生态地图”“机会清单”作为独立章节结论。它们只能作为证明顶层结论的中间证据。

### 建议页面序列

固定页数时按比例伸缩、合并或替换，不机械增页。用户指定页数/模板优先。

| 阶段 | 页面角色 | 必须完成的收敛 |
|---|---|---|
| 0 | 封面与执行摘要 | 一页说清建议、理由、需授权事项和时间窗口 |
| 1 | 企业处境与能力边界 | 从企业真实能力、经营现实和不做边界推导研究范围 |
| 2 | 全场景与全生态/责任链 | 从客户结果和价值/责任交接定位问题，不列投资清单 |
| 3 | 问题树与优先级 | 用MECE问题树/矩阵将全部问题压缩为少量优先产业链 |
| 4 | 重点产业链深钻 | 对每条链依次讲场景问题、完整链、路线/TCO、具体卡位产品 |
| 5 | 战投组合与阶段动作 | 将具体节点放入自做/采购/合作/投资/并购的反事实选择与阶段闸门 |
| 6 | 结论与授权 | 三项结论、近期行动、责任人、需领导决定事项和停止条件 |

## 3. 每页的行动标题与证据标准

每页标题必须是完整、可被证据支持或反驳的**结论句**，而不是主题名词。标题字面应能回答“这一页结束后，领导应该相信什么”。

| 不合格标题 | 合格标题结构 |
|---|---|
| “市场规模分析” | “[场景]需求存在，但只有[细分价值池]与[目标企业]接口匹配” |
| “生态地图” | “[两至三项责任短板]决定系统成本和准入，因而需要优先下钻” |
| “投资机会” | “[具体产品]能补齐[系统短板]，但须先证明[成本/工程/责任条件]” |
| “战略布局” | “近期先以[项目动作]验证；满足[证据]后才进入[资本工具]” |

每页遵守“**一个行动标题 + 最多三至五个支撑点 + 一个关键洞察/决策含义**”。如果关键结论无法在标题中写清，说明问题尚未收敛；先回到研究，不用更多图形掩盖。

## 4. 按问题选择MBB页面类型

| 要回答的问题 | 首选页面类型 | 规则 | 不应使用 |
|---|---|---|---|
| 问题为何发生 | Situation–Complication–Key Question、As-Is/To-Be | 明确不行动代价与核心问题 | 单纯背景段落 |
| 问题如何MECE拆分 | 问题树 | 同一层分支相互独立、合并穷尽；不超过三层 | 大量并列卡片 |
| 哪些方向优先 | 价值—可行性矩阵、漏斗、优先级表 | 轴、指标和判断方法清晰；气泡第三维必须有来源 | 无定义的“战略象限” |
| 产业责任如何传递 | 从左到右的价值/责任链、逻辑箭头 | 标明价值、风险、数据或责任的交接 | 与客户问题无关的部件罗列 |
| 技术路线如何取舍 | 对比表、成本瀑布、成熟度路径 | 每列都有对投资判断的含义；结论不只比较参数 | 只列技术名/专利/性能指标 |
| 市场和价值如何捕获 | TAM/SAM/SOM分层、价值池、商业模式树 | 从价值池到付费方、收费单元、现金流归属，再到可获得收入 | 把总市场等同于公司收入 |
| 如何行动 | 甘特图/路线图/阶段闸门 | 写动作、交付物、负责人、里程碑、升级与停止条件 | 抽象“短中长期”箭头 |
| 最终需决定什么 | 结论页 | 三点结论+行动清单+需领导授权 | 再列一遍所有发现 |

图表只在存在可靠数据时使用；没有数据时使用逻辑图、流程图或事实表，不得制造精确感。每张数据图表必须有来源、时间、口径、单位和“关键洞察框”。

## 5. MBB视觉与可编辑性规范

1. **保持模板优先。** 使用用户提供的公司模板、品牌色、字体和页眉页脚；若没有模板，采用克制的专业配色，主色不超过四种，不使用渐变、3D图表或装饰性图片。
2. **行动标题优先。** 标题占一行，正文保持克制。内容占画布不超过约60%，余下用于留白、逻辑分组和重点提示；无法做到时拆分或删减，而非将字体压缩到不可读。
3. **一页一问。** 每张页面只承担一个结论问题；相邻页必须能读出“上一页发现什么—本页证明什么—下一页如何行动”。
4. **数据可编辑。** 所有形状、箭头、表格、图表文字和数据源必须可编辑；图表不得只以截图嵌入。需要地图、产业链或矩阵时，保留Mermaid/CSV/Python或等效源文件。
5. **重点信息可扫读。** 关键数字、结论、风险、授权和行动应通过一致的颜色/加粗/关键洞察框标识；不要依靠复杂装饰、超长英文或过多术语。
6. **页脚一致。** 每页保持企业/项目名称、保密标注、页码和必要来源。用户已有模板时不得擅自改动固定页脚。
7. **演讲稿可用。** 每页生成50—150字的演讲稿：先说本页结论，再解释一至两条支撑，最后承接下一页；不逐字复述页面文字。

## 6. PPT反向审稿表

### 逻辑审稿

- [ ] 执行摘要独立成立：一页即可理解核心问题、建议、价值/风险、需要的授权和近期动作。
- [ ] 每页标题都是行动标题；每条标题均可由本页证据支持或被推翻。
- [ ] 整体符合金字塔：结论先行，之后的页面只负责证明或拆解结论。
- [ ] 场景、生态、产业链、产品和资本动作有明确收敛关系，未并列堆砌。
- [ ] 问题树、分类、矩阵和优先级满足MECE；没有重复维度、遗漏关键维度或无解释的“其他”。
- [ ] 所有建议均经过“维持现状—采购—合作—自建—投资—并购”的反事实比较。
- [ ] 最后一页能明确说出：本次需要谁在什么时间决定什么；若证据不足，明确请求的是下一步验证而非投资授权。

### 证据与经济性审稿

- [ ] 每张数据图标明来源、年份、口径、单位和关键洞察；每个预测标明假设。
- [ ] 每个卡位产品说明完整产业链、至少一条替代路线、TCO、付费方、收费单元、可获得收入边界与停止条件。
- [ ] 不存在无来源市场规模、无依据的技术领先、默认协同、自动获得数据/订单/接口或将法规责任混给错误主体。
- [ ] 正向建议包含至少一个成本、工程、认证、采购、服务、客户采用或竞争反证。

### 视觉与交付审稿

- [ ] 重点页已经渲染检查，文字无重叠、无越界、无超小字号、无不必要的卡片堆积。
- [ ] 图表配色、字体、间距、对齐、页脚、来源样式全篇一致；颜色不超过四种，图例和轴可读。
- [ ] 所有元素、源数据、图表、故事线文件和演讲稿可编辑，并已纳入导航。
- [ ] 最后一次PPT呈现后，已将最终链接同步进导航和主Excel。
