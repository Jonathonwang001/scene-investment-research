# 证据、经济性、术语与质量规范

> 在形成投资结论、估计市场/商业模式、处理法规或交付材料前读取。本文件定义“精品级”研究的最低证据、可读性、去敏和质检门槛。

## 1. 证据等级与表述强度

| 等级 | 典型来源 | 可直接支持 | 不可直接支持 | 推荐措辞 |
|---|---|---|---|---|
| A | 法规原文、标准、审计报告、监管文件、客户合同/公告、原始测试 | 事实、日期、指标、已发生事项 | 未披露的未来订单、协同、收益 | “公开文件显示”“法规规定”“已验证” |
| B | 年报、权威官网、招标、专利、同行评议、可靠媒体 | 公司公开口径、技术路线、公开案例 | 收入真实性、技术领先、必然商业化 | “公开披露称”“显示可能”“需交叉核验” |
| C | 演示材料、口头转述、营销文案、未核验第三方线索 | 研究假设、后续核验问题 | 关键结论、估值、市场份额、订单或协同 | “待核验”“作为线索”“未见独立证据” |

对会改变优先级、资源投入、估值、法规责任或停止条件的正面命题，优先获得两条相互独立的证据。若只能取得C级证据且存在成熟替代或反方证据，应降低结论强度或停止推进。

## 2. 总拥有成本（TCO）与工程化清单

不要只比较单价、材料价格或实验室指标。每条路线至少检查：

| 成本/约束类别 | 具体问题 | 对战略投资的含义 |
|---|---|---|
| 制造与采购 | 良率、产能、关键材料、供应集中度、采购价、交期 | “性能更好”可能无法转为可供应产品 |
| 部署与改造 | 安装、兼容、接口、空间、能耗、停机、培训、认证 | 初始价格低未必系统成本低 |
| 运行与维护 | 可靠性、故障率、寿命、备件、维护、软件升级 | 决定服务收入和质保责任 |
| 风险与责任 | 安全、信息安全、保险、质保、罚款、召回、法律角色 | 决定企业能否承担系统责任 |
| 数据与合规 | 数据接入、存储、授权、审计、隐私、供应商文件 | 合规软件/平台的实施成本常高于标签成本 |
| 切换与退出 | 双源验证、重新认证、迁移、退役、回收、资产残值 | 决定开放架构是否是真实优势 |

## 3. 市场规模与价值捕获纪律

每个市场规模或商业模式结论必须回答：地域、期间、产业环节、总市场（TAM）、可服务市场（SAM）、企业可获得收入（SOM）、数据来源及适用限制。没有可信数据时，不虚构数字；改用单位经济、收费单元和规模上限的定性判断。

| 商业模式 | 收费单元 | 典型价值捕获 | 必要验证 |
|---|---|---|---|
| 硬件/材料 | 单件、单套、重量、功率/容量 | 一次性毛利，易受价格竞争影响 | 规格导入、良率、供应链、售后成本 |
| 项目软件/工程 | 项目、站点、实施人天 | 实施收入，复用性有限 | 是否可配置、是否依赖大量定制 |
| 订阅软件 | 用户、设备、站点、容量、年度 | 经常性收入，依赖留存与数据/接口 | 付费方、续费、接入成本、功能不可替代性 |
| 数据/资产服务 | 资产、容量、报告、验证、保障 | 与运营、质保、保险或残值绑定 | 数据授权、准确性、采信、责任承担 |
| 交易/节省分成 | 交易额、节省成本、收入增量 | 上行大但结算、归因和现金流风险更高 | 合同、计量、分成比例、回款和可审计性 |

同一技术可能因商业模式变化而具有完全不同的市场和估值逻辑。必须将“按重量或单件出售”与“嵌入客户交易流后按服务/分成收费”分开建模；后者不得在没有合同、可计量价值或责任安排时写入基准预测。

## 4. 技术术语与领导可读性

1. 首次出现的非品牌英文术语，写作“**中文全称（英文全称，缩写）**”，随后用一句通俗解释说明它如何影响客户采购、成本、风险、交付或估值。
2. 领导页、图表标题和Excel表头优先使用中文业务名称；缩写仅作为检索、接口和跨专业沟通辅助。
3. 法规名称和编号可保留原称，但必须说明其业务含义、适用对象、角色和时间窗口。
4. 机会名称必须是产品化语言。例如，使用“跨品牌设备健康与剩余寿命诊断（健康状态算法＋设备数据适配＋资产报告）”，不要使用“智能运维机会”。
5. 若一个概念不能用两句话让非专业读者明白“是什么、解决谁的什么问题、为什么影响投资”，补证据、改写或降低结论，不要保留黑话。

## 5. 战略协同、项目验证与资本动作边界

| 常见误写 | 正确写法 |
|---|---|
| “投资后取得数据/接口/订单” | “在客户授权、合同、采购、测试或治理安排落实后，可验证……” |
| “合作即可形成协同收入” | “未签约协同不进入收入/回报；仅作为上行情景或待验证选项” |
| “技术先进，应该投资” | “技术需在场景、TCO、工程成熟度、责任与付费意愿上通过验证” |
| “战略投资等于控股全系统” | “战投只布局不宜自研但决定场景切入、系统责任或外部产品化的稀缺子环节” |
| “法规推动，市场必然巨大” | “法规仅创造责任/证据需求；需验证产品化、实施成本、付费方和替代路径” |
| “大公司做不了，所以有机会” | “说明其重资产/封闭体系的具体限制，以及目标企业可从哪个接口以更低TCO切入” |

## 6. 去敏规则

技能资源、模板、示例、脚本输出和最终交付说明中不得保留上一项目的下列内容：企业名称、证券代码、客户、供应商、项目地点、未公开收入/订单、内部预算、估值、技术参数、人员、聊天原话、合同条款或专有文件路径。

使用占位符，如`[目标企业]`、`[重点场景]`、`[目标区域]`、`[关键产品]`、`[法规/标准]`、`[时间窗口]`、`[项目入口]`。不要仅替换企业名称而保留可反向识别的描述、数值组合或独有措辞。

## 7. 最终跨文件质检清单

### 内容与证据

- [ ] 事实、企业材料、第三方线索、内部假设和待核验事项已分开。
- [ ] 所有重要法规均核对原文、角色、适用对象、生效日期和二级规则状态。
- [ ] 每个重点产品有完整产业链、主流/替代路线、至少一个反方问题、工程/TCO与商业模式。
- [ ] 市场规模、收入、协同、订单和数据权利没有被无证据外推。

### 战略与经济性

- [ ] 每个卡位产品写清企业为什么能切入、企业自做/采购/合作/战投分工、阶段动作和不做边界。
- [ ] 每项股权建议均说明升级证据与停止条件；早期项目可接受未盈利但不可接受只有概念。
- [ ] 法规、工程、成本与商业模式共同决定近期/中期/远期，而不是技术时髦程度。
- [ ] 商业模式明确收费单元、付费方、复购、现金流归属和市场边界。

### 叙事与可编辑交付

- [ ] 双报告、Excel、PPT和导航的产品名称、阶段、法规日期、来源和链接完全一致。
- [ ] PPT主线单向递进；每页只回答一个问题；卡片不孤立、术语不未解释、无文字重叠或越界。
- [ ] Excel先放领导总览、近期行动和阶段闸门；将场景/生态/产业链原始信息下沉为后台明细。
- [ ] 所有图表、表格、形状、文字、源数据与逻辑文件均可编辑。
- [ ] 完成去敏审计，未保留上一项目可识别信息。
